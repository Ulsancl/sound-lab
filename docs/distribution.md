# 배포 범위와 확인 기준

이 문서는 Sound Lab 1.1의 유한한 기능 범위와 배포 확인 기준입니다. 실제 통과·설치·공개 상태는 각 버전의 결과 기록을 따릅니다. 최종 후보의 검증과 공개 파일 대조가 끝나기 전에는 배포 완료로 판단하지 않습니다. 개발자에 의한 앱 검사는 실제 사용자 연구·판매·유료 지원 검증을 뜻하지 않습니다.

`npm run package:desktop`은 설치 및 개발 검사용 서명 없는 설치 파일과 `.sha256`을 `release/windows`에 만듭니다. 버전은 package.json을 따릅니다. 설치 앱은 화면·모형·라이브러리를 로컬에 포함하며 새 설치 파일로 수동 업데이트합니다. 제거 설정은 사용자 앱 데이터를 보존합니다.

공개용 Windows 패키지는 신뢰된 Windows 빌드 환경에서 `npm run package:desktop:release`로 생성합니다. 관리자가 제공한 유효한 Authenticode 서명 자격 증명을 electron-builder에 구성하고, 승인된 인증서 지문을 `SOUND_RELEASE_SIGNER_THUMBPRINT`에 지정합니다. 설치 파일과 앱 실행 파일에 유효한 타임스탬프 서명이 있고 두 지문이 승인된 값과 일치할 때 체크섬을 만들고 결과를 게시합니다. 서명과 공개는 별도 단계입니다. 공개한 파일의 서명은 신뢰된 경로로 받은 지문과 `node scripts/verify-release.mjs <설치 파일 경로>`로 대조할 수 있습니다. 같은 배포 경로의 SHA-256은 파일 무결성 확인에 사용합니다.

배포 전에는 모형의 주파수·마디·부호 관계, 엄격한 파일 왕복과 원문 보호, 실제 세 안내 실험·구조 관찰·비교 축, 위상 정지와 오디오 중단을 확인합니다. 조건을 바꿀 때 조작 옆의 실제 Hz와 고조파 배수를 함께 읽을 수 있어야 합니다. 소스·패키지·실제 설치 앱의 네이티브 메뉴·파일·재시작은 실행 대상을 구분해 기록합니다. 소스와 ASAR·문서·라이선스 고지·설치 파일의 해시를 대조하고, 보존한 구버전의 입력·시점·원문을 새 버전이 그대로 복원하는지 확인합니다.

Windows CI는 순수 검사, 브라우저 조작, 소비자 관찰, 상세 계측·내부 관찰, 소스 네이티브, 패키징과 패키지 네이티브를 순차 실행합니다. 로컬 실제 설치·구버전 업데이트, 원격 CI, 공개 저장소·태그·다운로드 파일의 검증은 별도 결과입니다. 어느 하나의 성공을 다른 단계의 성공으로 대신하지 않습니다.

Web Audio의 오프라인 표본 검사는 발진 주파수·길이·gain을 확인할 수 있지만 사람의 실제 청취, 스피커 음량·음질·dB 측정의 증거가 아닙니다. 오디오 실패는 수치·화면 관찰을 막지 않아야 합니다. 로컬 하드웨어 근거는 기록된 Windows 11 x64·RTX 5080·150% 배율과 실제 검사한 창 크기에 한정합니다. CI의 가상 그래픽 장치 결과를 실제 GPU·모든 기기·원격 데스크톱·다른 운영체제까지 확대하지 않습니다.

관의 길이·경계·모드 선택은 새로운 고유모드를 고르는 조작입니다. 모드 사이 과도응답, 공명 폭·Q·감쇠, 끝단 보정·실제 음압·음향 안전을 계산한 것으로 설명하지 않습니다. 상대 압력 색과 가시화한 입자 왕복은 실측 자료가 아닙니다.
